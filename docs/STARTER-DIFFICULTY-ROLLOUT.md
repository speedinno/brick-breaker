# Easier opening rounds — rollout notes

Build 23 changes stages 1–2 to ten-tile entrances, stage 3 to eight tiles, stage 4 to six, stages 5–8 to four, and stages 9–12 to the original two. Early stages have a wider paddle, gentler speed and more frequent boosts. A free paddle shooter begins every launch in stages 1–8; its duration tapers from 12 to 1 second. The launch still serves one ball, so players steer and catch later pickups. Starter motifs are reordered to teach short, open paths before crossing chambers without repeating a motif. Every eighth stage from 20 remains a Breather with more forgiving play controls. Later-stage layouts do not change.

An integrated delayed-input controller, which follows a descending ball only every quarter second and does not choose strategic angles or pickups, cleared stage 1 in 5/5 seeded runs with no lost lives; stages 2–4 cleared 4/5, 4/5 and 3/5. Successful stage 1 runs took 89–277 simulated seconds. This repeatable proxy tests the real manual engine, but it is not a human win rate or proof of a satisfying session. Ask first-time players to attempt the opening rounds on physical phones without AUTO and record clear time, retries, aim confusion and whether they want to continue. Tune again if the first win still takes repeated frustrating attempts.

Signed-in players use a shared catalog. Existing version 3 and 4 starter rows and runs must remain in place so previously started stages can finish against their original hashes. Build 23 uses catalog version 5 for stages 1–12; stage 13 onward remains version 3. Completion history remains stored as the existing progress edition (version 3), so completion ticks and records do not split between catalog revisions.

Before shipping build 23 on Android/iPhone/web, apply any pending `202610280016_starter_catalog_v4.sql` followed by `202610280017_starter_catalog_v5.sql` through the established migration process and deploy the matching API bundle. The new migration retains v3/v4 rows and in-flight runs and routes new starter runs to v5. Then use two disposable signed-in accounts to fetch a revised starter, start/complete it, and confirm the completion tick, history and cross-device sync. Test already started v3 and v4 runs before their expiry as well. Check a newly generated stage above 12 still uses v3.

Do not ship the client before backend migration and API deployment: its v5 starter validation will reject old shared definitions. Keep a record of the migrated schema revision, deployed API image and client commit for the release. A physical phone playtest should confirm the opening feels wide enough and stage 1 can be won without repeated frustrating retries; automated clearability alone cannot establish this.

The pasted review also identified control focus/swipe behavior, purchase retry recovery, backend test and native acceptance issues. The controller, checkout guard and stale backend test have been fixed in this branch and passed targeted software checks. Packaged Android/iPhone gameplay acceptance is tracked in [mobile build evidence](MOBILE-BUILD-3.3.md); do not claim physical-player ease from emulator/simulator checks. The public GitHub Pages demo is still the older 3.0 edition and is labelled that way in the README.
